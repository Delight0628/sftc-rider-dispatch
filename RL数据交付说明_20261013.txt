二、RL模型41维特征 ↔ 源字段映射
--------------------------------------------------------------------
【rider_feat 骑手特征 8维】
  载荷率(load_ratio)      <- total_distance / capacity(需运行时计算,
                            原始量: total_distance, stra_riding_distance)
  忙碌比(busy_ratio)       <- 运行时窗口统计(原始量: 时间链各时间戳)
  离线状态(offline)        <- work_status(骑士9列)
  速度(speed)              <- total_distance / distribution_duration
  容量(capacity)           <- vehicle_type(车型映射容量) + weight_gram
  free_delay               <- arrive_shop_duration / wait_duration
  pos_x / pos_y            <- arriveshop_lng / arriveshop_lat
  (骑手画像: ucode, level, work_type, vehicle_type, rider_sex,
   work_status, extra_flag, team_id, station_id 已全量附上)

【cand_feat 候选单特征 12维】
  dispatch_bias            <- dispatch_type / group_type
  due_rel(相对截止)        <- latest_delivery_time - order_time
  取餐耗时                 <- pickup_duration / arrive_shop_duration
  全程耗时                 <- distribution_duration
  拥堵系数                 <- nav_estimated_duration / distance_km
  优先级(priority)         <- priority_order_type
  is_urgent                <- order_kind / priority_order_type
  type_id                  <- business_type_name / product
  迟到风险(latency_risk)   <- promise_delivery_time vs finish_time分布
  slack                    <- latest_delivery_time - estimated_delivery_time
  rank                     <- (按候选打分运行时排序)

【global_feat 全局特征 5维】
  <- weather_level, aoi_press, dim_area, super_city_name,
     is_night_send(夜间单比例)

【edge_feat 边特征 16维】核心打分通道
  12维基线: 距离/ETA/方向角等 <- distance_km, total_distance,
     shop/user/arriveshop/pickup/finish 的 lng/lat(8个GPS坐标),
     estimated_delivery_time, nav_estimated_duration
  4维exp-b:
    eta_congestion         <- nav_estimated_duration vs 实际distribution_duration
    dropoff_cluster        <- user_real_aoi_id / grid_id(落单聚类)
    pickup_contention      <- shop_real_aoi_id(取餐竞争度)
    rider_fatigue          <- wait_duration / dish_time(骑手疲劳度)

四、数据质量核查结论(交付前已全量对拍)
--------------------------------------------------------------------
1. order_id 与双塔&D&W训练数据(pairs3) 30000/30000 全等,
   rider_ucode_accept 一致率 100%, order_received_time/distance_km
   一致率 100% —— 确认同一批订单同一批接单骑手。
2. 坐标列(shop/user/arriveshop等)按4位小数存储, 与双塔源数据
   全量数值等价(差<1e-4度, 100%)。
3. finish_lng/finish_lat 约48%为0(源表未记录完成坐标), 做
   落单/终点分析时请过滤=0的行; 其余坐标均在境内范围。
4. 下单->完成时长中位数0.55小时, 负值占比0.02%(跨零点尾单),
   时间戳字段单位为秒(epoch)。
5. distance_km 中位数0是源表特征(近距离/同点单较多), 与双塔
   源数据完全一致, 非取数错误。

五、使用提示
--------------------------------------------------------------------
1. 时长类字段单位为秒, total_distance/stra_riding_distance为米,
   distance_km为公里, weight_gram为克。
2. 仿真运行时状态量(载荷率/忙碌比/候选rank等)需在环境里按
   时间戳回放计算, 本表提供的是全部原始观测量。
3. 骑士9列来自双塔&D&W同款维表(按rider_ucode_accept关联),
   保证两边模型骑手画像完全一致。
